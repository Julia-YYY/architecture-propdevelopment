## 2. Выбор разделов и обоснование

Приоритеты компании из описания:

1. **Нарушен контроль данных.** Есть несколько точек регистрации, потоки между продуктами не контролируются, доступ к данным в DWH не ограничен.
2. **API партнёров.** Нет единых политик, ПДн раскрываются в контрактах, данные разных УК не изолированы (нарушена авторизация на уровне объектов, BOLA).
3. **Рост через партнёрские сервисы**, в том числе «Умный дом», который управляет физическим доступом и биометрией.
4. **Организационная проблема.** Специалист ИБ один на всю компанию, после смены руководителей команд он получает не все решения и изменения.
5. Подготовка к **комплексному аудиту**. Гибридная инфраструктура: собственный ЦОД, приватное облако, арендованные мощности и временные облачные ресурсы для тестов.

| Раздел | Включён | Обоснование |
| --- | --- | --- |
| I. Управление доступом | Да, полностью | Это основа решения обеих проблем. Сейчас несколько точек регистрации, два Keycloak и два AD, у партнёров есть доступ к чужим данным, к DWH доступ не ограничен. Без единого реестра учётных записей, минимальных привилегий и ABAC (изоляция по УК и ЖК) проблемы не решить |
| II. Безопасность данных | Да, полностью | Ключевая проблема компании. Классификация данных уже сделана в задании 1, её нужно закрепить политикой, шифрованием, учётом ПДн, Data Governance и анонимизацией перед загрузкой в DWH |
| III. Защита инфраструктуры | Да, полностью | Гибридная инфраструктура с выходом в интернет. Межсетевой экран есть только на периметре, про сегментацию и фильтрацию между сегментами данных нет. Временные облачные ресурсы для тестов — типичная точка утечки, поэтому нужно сканировать облако на соответствие требованиям |
| IV. Управление инцидентами | Да, полностью | Специалист ИБ один и видит не все изменения, поэтому нужны автоматические мониторинг и оповещения (SIEM). Партнёрские интеграции и физический доступ через «Умный дом» требуют быстрого реагирования |
| V.1. Общие вопросы | Да | Удалённый доступ сотрудников и подрядчиков, резервное копирование в облаке (часть продуктов в гибриде) |
| V.2. Оборудование и физическая безопасность | Да, сокращённо | У компании собственный ЦОД, поэтому СКУД и инвентаризация обязательны для аудита. Эти вопросы не связаны с ключевыми проблемами, их приоритет ниже |
| **VI. Безопасность интеграций и API партнёров (добавлен)** | Да | В шаблоне нет отдельного раздела по API, а это вторая ключевая проблема. Вопросы построены по OWASP API Security Top 10 (2023): BOLA, чрезмерное раскрытие данных, аутентификация партнёров, контракты и лимиты |
| **VII. Процессы ИБ и управление изменениями (добавлен)** | Да | Решает организационную проблему: решения и изменения не доходят до специалиста ИБ. Нужен обязательный security review в процессе изменений и назначенные ответственные (security champions) в командах |

Обозначения в колонке «Да/нет»: **Да**, **Нет**, **Частично**, **Н/Д** — нет данных, вопрос нужно уточнить на интервью при аудите.
